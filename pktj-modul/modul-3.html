3.1 Hubungan Aplikasi dengan Kebutuhan Jaringan

Aplikasi adalah alasan utama jaringan dibangun. Orang tidak butuh "internet 100 Mbps" — mereka butuh bisa video call, upload tugas, akses sistem sekolah. Dari daftar aplikasi inilah kita menghitung kebutuhan jaringan.

Tiga Karakteristik Aplikasi yang Menentukan Kebutuhan

Bandwidth
  • Seberapa besar data yang mengalir per detik?
  • Diukur dalam Mbps (Megabit per second).
  • Menentukan kapasitas link dan jumlah client.
Latency
  • Seberapa cepat respons diterima?
  • Diukur dalam ms (milidetik).
  • Menentukan kelancaran aplikasi real-time.
Jitter & Packet Loss
  • Seberapa stabil pengiriman data?
  • Jitter = variasi latency.
  • Packet loss = data hilang di jalan.

3.2 Web Browsing & Cloud Application

Aplikasi paling umum di jaringan modern. Meski terlihat ringan, browsing dan aplikasi cloud modern makin lama makin "berat" karena kontennya kaya.

Karakteristik

  • Bursty — trafik naik-turun cepat saat halaman dimuat.
  • Tidak terlalu sensitif latency — ratusan ms masih terasa "normal".
  • Cache-friendly — banyak konten diulang, bisa dioptimalkan.
  • Bisa sangat besar — Google Drive, OneDrive, video web.

Kebutuhan Umum

KegiatanBandwidth
Buka halaman web sederhana0.5–1 Mbps
Buka halaman dengan gambar besar2–5 Mbps
Google Docs / Office 3651–3 Mbps
Upload ke Google DriveSampai batas uplink
Download file besarSampai batas downlink
Catatan

Browsing terasa ringan, tapi kalau 100 orang browsing bersamaan, totalnya bisa ratusan Mbps. Concurrent users tetap jadi kunci.

3.3 File Sharing

Berbagi file dalam jaringan lokal (LAN) atau lewat internet. Karakternya bergantung pada ukuran file dan frekuensinya.

Dua Konteks File Sharing

LAN (Lokal)
  • File server, NAS, shared folder.
  • Bandwidth sangat tinggi (100 Mbps–1 Gbps).
  • Latency sangat rendah.
  • Tidak pakai bandwidth internet.
Cloud / Internet
  • Google Drive, OneDrive, Dropbox.
  • Terbatas bandwidth internet.
  • Upload sering jadi bottleneck.
  • Bergantung kualitas ISP.

Pertanyaan untuk Pengguna

  • Berapa rata-rata ukuran file yang ditransfer?
  • Berapa sering transfer dilakukan?
  • Apakah transfer ke server lokal atau ke cloud?
  • Apakah butuh transfer bersamaan oleh banyak orang?
Tips

File besar lebih baik lewat LAN (server lokal). File kecil/sering dibagikan lintas lokasi lebih baik lewat cloud.

3.4 Video Conference

Aplikasi paling sensitif kedua setelah VoIP. Video conference butuh bandwidth stabil, latency rendah, dan jitter kecil — kalau tidak, gambar akan patah-patah.

Contoh Aplikasi

Zoom, Google Meet, Microsoft Teams, Webex, WhatsApp Video, Skype.

Kebutuhan Bandwidth (per arah)

KualitasDownlinkUplink
SD (360p)0.5–1 Mbps0.5–1 Mbps
HD (720p)1.5–2 Mbps1.5–2 Mbps
Full HD (1080p)3–4 Mbps3–4 Mbps
Group HD (720p)2–3 Mbps1–2 Mbps

Parameter Kritis

  • Latency < 150 ms — kalau lebih, percakapan terasa "delay".
  • Jitter < 30 ms — kalau lebih, suara patah-patah.
  • Packet loss < 1% — kalau lebih, gambar pecah.
Perhatikan Uplink

Video conference butuh uplink, bukan hanya downlink. Banyak jaringan dirancang hanya fokus downlink, sehingga video call tetap bermasalah.

3.5 Streaming

Menonton konten video/audio secara langsung. Karakter: one-way, bandwidth besar, buffer-friendly.

Contoh Aplikasi

YouTube, Netflix, Spotify, Twitch, video pembelajaran (Rumah Belajar, Zenius).

Kebutuhan Bandwidth

KualitasBandwidth
Audio saja (Spotify)0.1–0.3 Mbps
360p0.7 Mbps
480p1.1 Mbps
720p2.5 Mbps
1080p5 Mbps
1440p (2K)8 Mbps
2160p (4K)25 Mbps

Karakteristik Penting

  • Buffer — pemutar video menyimpan beberapa detik data ke depan. Gangguan jaringan sesaat tidak langsung terasa.
  • Download-heavy — menguras bandwidth downlink, kurang masalah di uplink.
  • Mudah di-cache — konten populer bisa di-cache di proxy.
  • Sensitif bandwidth, tidak terlalu sensitif latency.
Tips

Kalau banyak pengguna streaming, pertimbangkan QoS atau bandwidth limit per user agar tidak menghabiskan bandwidth untuk hal non-kritis.

3.6 VoIP

Voice over IP — telepon melalui jaringan data. Bandwidth kecil, tapi paling sensitif terhadap latency, jitter, dan packet loss.

Contoh

Telepon kantor berbasis IP, WhatsApp Call, Discord Voice, SIP Trunk.

Kebutuhan

  • Bandwidth: 0.1 Mbps per panggilan (codec G.711 ~ 87 kbps; G.729 ~ 30 kbps).
  • Latency: < 150 ms (ideal < 100 ms).
  • Jitter: < 30 ms.
  • Packet loss: < 1%.

Kenapa VoIP Sangat Sensitif?

Berbeda dengan streaming yang bisa di-buffer, VoIP adalah komunikasi dua arah real-time. Kalau data terlambat 200 ms, percakapan mulai terasa aneh. Kalau jitter tinggi, suara patah-patah. Kalau packet loss tinggi, ada bagian suara yang hilang.

Penting

VoIP wajib dapat prioritas QoS. Kalau disamakan dengan streaming atau download, kualitas panggilan akan hancur.

3.7 Sistem Informasi & Database

Aplikasi internal organisasi: sistem akademik, keuangan, absensi, HR, ERP. Biasanya berbasis web dengan backend database.

Karakteristik

  • Traffic kecil–sedang — query database umumnya ringan.
  • Bursty — saat generate laporan, traffic naik tajam.
  • Sensitif latency — query yang lambat terasa di UI.
  • Kritis untuk bisnis — kalau down, operasional berhenti.

Pertimbangan

AspekPerhatian
Lokasi serverLokal (LAN) vs cloud
Jumlah user concurrentMenentukan kapasitas server
Frekuensi queryMenentukan load database
Ukuran dataLaporan besar butuh bandwidth besar
BackupButuh bandwidth & storage terjadwal
Catatan

Aplikasi internal sering under-estimated. Saat ujian online serentak, ratusan siswa mengakses sistem akademik — traffic melonjak drastis.

3.8 CCTV / IP Camera

Kamera pengawas berbasis IP. Karakternya kontinu dan bandwidth-heavy, terutama kalau resolusinya tinggi.

Kebutuhan Bandwidth per Kamera

ResolusiFPSBandwidth
720p (HD)151–2 Mbps
1080p (Full HD)252–4 Mbps
1440p (2K)254–6 Mbps
2160p (4K)308–12 Mbps

Poin Penting

  • Selalu aktif 24/7 — tidak ada jam sepi.
  • Kabel lebih baik — biasanya pakai PoE (Power over Ethernet).
  • Tidak boleh putus — packet loss berarti kehilangan bukti rekaman.
  • Akses remote — kalau dipantau dari luar, butuh uplink besar.

Hitung Cepat

Total BW CCTV = jumlah kamera × BW per kamera

Contoh: 16 kamera 1080p × 3 Mbps = 48 Mbps
Jangan Lewatkan

CCTV termasuk aplikasi yang paling cepat menghabiskan bandwidth. 20 kamera saja bisa memakan 60–80 Mbps terus-menerus.

3.9 Pembelajaran Daring

Gabungan beberapa aplikasi sekaligus: video conference, akses LMS, upload tugas, streaming materi. Ini yang membuat pembelajaran daring "berat".

Contoh Skenario

  • Guru mengajar via Zoom (3 Mbps).
  • Siswa menonton + bertanya via chat (2 Mbps).
  • Siswa upload tugas ke Google Classroom (2–10 Mbps burst).
  • Siswa akses materi di LMS (1–3 Mbps).
  • Total per siswa: 3–8 Mbps dalam sesi aktif.

Implikasi untuk Sekolah

Jumlah siswa aktifEstimasi bandwidth
30 siswa (1 kelas)90–240 Mbps
150 siswa (5 kelas)450 Mbps – 1.2 Gbps
500 siswa1.5 – 4 Gbps
Tips

Kalau bandwidth internet terbatas, batasi jumlah siswa yang video-on sekaligus. Siswa lain cukup audio + slide.

3.10 Aplikasi yang Membutuhkan Bandwidth Besar

Ini daftar aplikasi yang paling menguras bandwidth. Kalau ada di jaringan Anda, siapkan kapasitas ekstra.

AplikasiBandwidth
Streaming 4K25 Mbps / user
Video conference HD group3–4 Mbps / user
CCTV 4K8–12 Mbps / kamera
Transfer file besar (cloud)10–100 Mbps
Backup ke cloudBisa jenuh uplink
Update OS massalBisa ratusan Mbps
Video editing kolaboratif50–200 Mbps
Rendering / upload videoBisa jenuh uplink berjam-jam

Prinsip

  • Hitung berdasarkan waktu puncak — bukan rata-rata.
  • Prioritaskan traffic penting — pakai QoS.
  • Jadwalkan traffic besar — backup di luar jam kerja.
  • Batasi traffic non-kritis kalau perlu.
Contoh

Backup harian server 100 GB butuh ~9 jam kalau uplink 25 Mbps. Kalau dilakukan jam kerja, seluruh kantor akan terasa lambat. Jadwalkan tengah malam.

3.11 Aplikasi yang Sensitif terhadap Latency

Ada aplikasi yang bandwidth-nya kecil tapi rusak total kalau latency-nya tinggi. Ini yang sering membuat teknisi bingung: "bandwidth masih lega, kok lambat?".

Daftar Aplikasi Sensitif Latency

AplikasiBatas Latency
VoIP< 150 ms
Video conference< 150 ms
Online gaming (FPS)< 50 ms
Video conference (interaktif)< 100 ms
Remote desktop (RDP)< 50 ms
Sistem keuangan real-time< 100 ms
VoIP call center< 100 ms
Kontrol industri (SCADA)< 20 ms

Rumus "Sensasi Delay"

Round Trip Time (RTT) = 2 × latency

Manusia mulai terasa "delay" pada RTT > 300 ms
Video call mulai patah-patah pada jitter > 30 ms
Penting

Untuk aplikasi sensitif latency, QoS wajib. Tanpa QoS, download file besar bisa mengganggu VoIP meski bandwidth masih lega.

3.12 Analisis Kebutuhan Aplikasi Pengguna

Ini tahap penutup Modul 3 — mengubah daftar aplikasi menjadi kebutuhan jaringan yang terukur.

Langkah Analisis

  1. Daftarkan semua aplikasi yang dipakai pengguna (dari URL Modul 2).
  2. Kelompokkan berdasarkan jenis: browsing, video, VoIP, file, dsb.
  3. Cari profil trafik tiap aplikasi (bandwidth, latency, jitter).
  4. Estimasikan concurrent users untuk tiap aplikasi di jam puncak.
  5. Hitung total bandwidth: Σ (jumlah user × BW per user × overhead).
  6. Identifikasi aplikasi kritis yang butuh QoS.
  7. Susun Application Requirement List sebagai output.

Contoh Analisis — Ruang Guru

Aplikasi User BW/user Total
Browsing & email121 Mbps12 Mbps
Sistem informasi sekolah81.5 Mbps12 Mbps
Video conference HD23 Mbps6 Mbps
Streaming materi35 Mbps15 Mbps
Print server21 Mbps2 Mbps
Total mentah47 Mbps
Dengan overhead 1.3~61 Mbps

Output: Application Requirement List

IDAplikasiBWLatencyQoS
ARL-01Browsing & email12 MbpsRendahTidak
ARL-02Sistem informasi12 MbpsSedangYa (Medium)
ARL-03Video conference6 MbpsTinggiYa (High)
ARL-04Streaming15 MbpsSedangTidak
ARL-05Print server2 MbpsRendahTidak
Kunci

Application Requirement List adalah jembatan antara kebutuhan pengguna (Modul 2) dan kebutuhan teknis (Modul 4). Dari sini baru masuk ke bandwidth, latency, QoS.

Latihan

Sebuah kantor kecil dengan 15 karyawan memakai:

  • Email & browsing (semua karyawan)
  • Sistem ERP (10 karyawan)
  • VoIP (semua karyawan, ~5 panggilan bersamaan)
  • Video conference (2 karyawan)
Hitunglah: total bandwidth yang dibutuhkan, aplikasi mana yang butuh QoS, dan estimasi langganan internet minimum.

Poin Kunci Modul 3

  1. Aplikasi adalah alasan utama jaringan dibangun.
  2. Setiap aplikasi punya tiga karakteristik: bandwidth, latency, jitter.
  3. Bandwidth kecil tapi latency sensitif → VoIP, gaming, remote desktop.
  4. Bandwidth besar tapi latency toleran → streaming, cloud upload.
  5. Video conference dan VoIP butuh uplink, bukan cuma downlink.
  6. CCTV selalu aktif 24/7 — hitung dengan benar sejak awal.
  7. Pembelajaran daring adalah gabungan aplikasi, bukan satu aplikasi.
  8. Output Modul 3: Application Requirement List sebagai jembatan ke Modul 4.
